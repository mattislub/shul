# תוכנית אתר התרומות "בונים יחד את בית ה'"

## חזון וחוויית משתמש
מטרת האתר היא לאפשר לתורמים חוויה מוחשית ומרגשת של שותפות בבניית בית הכנסת. כל תורם רואה בדיוק את הפריט שעליו הוא משתתף – בין אם מדובר באבן, כיסא, אריח, חלון או פרוכת – ויכול להוסיף הקדשה אישית שתוצג על הפריט עצמו.

## מבנה כללי של האתר

### דף הבית
- וידאו או הדמיה של בית הכנסת בתהליך בנייה (אפשרי גם מודל תלת־ממדי פשוט שניתן לסיבוב).
- טקסט קצר המציג את הפרויקט: "בונים יחד את בית ה'".
- כפתור קריאה לפעולה בולט: **"בחר את חלקך בבניין"** שמוביל לדף התרומה.

### דף התרומה (הדף העיקרי)
- תצוגה אינטראקטיבית של חלוקת הפריטים (למשל גריד של אריחים או שורות של כיסאות).
- צבעים לפי סטטוס: ירוק = פריט פנוי, אפור = פריט שכבר נתרם.
- לחיצה על פריט פנוי פותחת חלונית הכוללת:
  - מחיר התרומה.
  - שדה כתיבה להקדשה אישית.
  - אפשרות לבחור האם ההקדשה תוצג לציבור.
  - טופס תשלום מאובטח (אשראי / העברה בנקאית / Bit).

### דף "בית הכנסת הבנוי"
- הדמיה עתידית מלאה המציגה את בית הכנסת לאחר השלמת הבנייה.
- סימון שמות התורמים על הפריטים שנרכשו.
- שדה חיפוש: "חפש את השם שלך בבניין" למציאת הקדשות לפי שם תורם.

### דף "רשימת התורמים"
- גלריה או טבלה המציגה את כל התורמים וההקדשות.
- אפשרות לסינון לפי סדר תרומה, גובה תרומה או סוג הפריט.

## רעיונות UX/UI לחוויית משתמש
- אנימציה חלקה שמדמה מעבר ממצב "לפני הבנייה" למצב "לאחר הבנייה" (Fade, Morph או שילוב).
- אפשרות לשתף בקלות ברשתות החברתיות: "תרמתי את הכיסא שלי בבית הכנסת החדש!".
- מצבי צפייה שונים: יום/לילה, פנים/חוץ.
- שימוש במיקרו־אנימציות להצגת סטטוס הפריט בעת מעבר עכבר (hover).

## ארכיטקטורה טכנית מוצעת

| חלק | טכנולוגיה מוצעת | תיאור |
|------|------------------|--------|
| Frontend | React / Next.js | תצוגה אינטראקטיבית והדמיה תלת־ממדית בסיסית עם תמיכה ב-SSR ל-SEO. |
| Backend | Node.js + Express | ניהול לוגיקת תרומות, פריטים, תשלומים ואוטנטיקציה. |
| Database | PostgreSQL / MySQL | שמירת סטטוסים של פריטים, תורמים והקדשות. |
| תשלומים | Tranzila / Z-Credit / PayMe | אינטגרציה לתשלומים מאובטחים. |
| העלאת שמות | Image Processing / Three.js | חיבור לאוטומציה שמוסיפה שם על תמונה או מודל תלת־ממד. |
| עיצוב | Tailwind CSS + Framer Motion | עיצוב עקבי עם אנימציות חלקות ואווירה יוקרתית. |

### תרשים זרימת נתונים (גבוה־רמה)
1. משתמש בוחר פריט → הבקשה נשלחת ל-API לוודא שהפריט עדיין פנוי.
2. השרת מחזיר אישור ומחיר → המשתמש ממלא פרטי תורם והקדשה.
3. השרת יוצר טרנזקציה מול ספק התשלום.
4. לאחר אישור, הסטטוס של הפריט מתעדכן ל"נרכש", נשמרות פרטי התורם וההקדשה בבסיס הנתונים, ונשלח מייל אישור.
5. לוח הבקרה מציג עדכון בזמן אמת ומאפשר ייצוא רשומות.

## מערכת ניהול (Admin)
- הוספה ועריכה של פריטים (סוג הפריט, מחיר, מיקום בהדמיה).
- עדכון סטטוס (פנוי / בתהליך / נרכש) עם הערות פנימיות.
- ניהול תורמים והקדשות, כולל אפשרות להסתיר הקדשה ציבורית.
- ייצוא נתונים לקובצי Excel או PDF לצורך הנהלת חשבונות ודיווח.
- הרשאות מבוססות תפקידים (מנהלי מערכת, אנשי שיווק, נציגי תמיכה).

## שיקולי אבטחה ויציבות
- שימוש ב-HTTPS מלא ובשירות תשלומים מאושר PCI.
- אימות דו-שלבי למנהלי מערכת.
- גיבוי יומי של בסיס הנתונים ושחזור מהיר.
- ניטור אנליטיקות (Google Analytics / Plausible) לצד ניטור ביצועים (Sentry / Datadog).

## עיצוב והשראה
- **צבעים:** זהב, לבן ואבן טבעית ליצירת תחושת קדושה ופאר.
- **פונטים:** כותרות בפונט עברי מעוגל ומכובד, טקסט גוף בפונט קריא ונקי.
- **טקסטורות ורקעים:** טקסטורות אבן בהירה או שיש המזכירים בית כנסת מפואר.
- **דגשים ויזואליים:** קווי אור זהובים, אייקונים בעיצוב קלאסי, ומסגור עדין סביב אזורי תוכן חשובים.

## צעדים הבאים
1. הכנת Wireframes למסכי המפתח וקבלת אישור בעלי העניין.
2. בניית Prototype אינטראקטיבי ב-Figma עבור זרימת התרומה.
3. הגדרת סביבת פיתוח (Monorepo עם Next.js ו-Express או פרויקטים נפרדים).
4. אינטגרציה עם ספק התשלומים הנבחר ובדיקות QA.
5. השקת גרסת Beta לאיסוף משוב מהתורמים הראשונים.
